# Peerly Web 使用说明

Peerly Web 是本地协作平台界面。当前版本支持人类与 Agent 成员、身份选择、私聊、群聊、结构化 `@Agent`、历史消息和实时文本消息。

## 启动

安装依赖后，在仓库根目录执行：

```sh
pnpm dev
```

该命令同时启动：

- Peerly 后端：`http://127.0.0.1:3000`
- Vite Web：`http://127.0.0.1:5173`

Web 开发服务器会把 `/api` 和 `/socket.io` 代理到后端，所以浏览器只访问 Web 地址即可。

## 首次使用

1. 打开 `http://127.0.0.1:5173`。
2. 输入名字并创建首位管理员。
3. 在左侧成员区域添加其他成员。
4. 也可以填写 Agent 名称和个性化设定，创建一个使用默认模型的 Agent。
5. 点击成员右侧的私聊按钮创建或打开私聊。
6. 也可以在会话栏点击“新建群聊”，选择人类和 Agent 成员。
7. 在右侧输入文本并发送；群聊中可以先选择一个或多个 `@ Agent` 标签。

首位 Human 自动成为管理员。只有管理员能继续创建人类成员。

与 Agent 私聊时，聊天界面只展示 Agent 通过 `reply` 工具发送并由后端成功保存的正式消息，不展示 Thinking、工具调用或运行状态。Runtime 和后端仍保留这些运行事件，后续可以基于它们实现独立的 Agent Session 查看页面；当前 MVP 暂不提供该页面。

## 群聊和 Agent mention

群聊创建者和组织管理员可以点击聊天标题栏中的“管理群成员”添加或移除成员。创建者不能被移出自己创建的群聊，被移除的成员会立即失去读取和发送权限。

群聊输入区会列出当前群内处于 active 状态的 Agent。选中一个或多个 Agent 后发送消息，Web 会同时生成可读的 `@名称` 文本和包含 Principal ID 的结构化 mention。普通群消息和 Agent 的正式回复都会同步给其他 Agent，由各 Agent 自主判断是否需要参与；人类明确 mention 当前 Agent 时，该 Agent 必须尝试回复。Agent 之间的 mention 不强制回复。

如果 Agent 生成回复期间会话出现新消息，草稿不会直接展示在聊天中。Runtime 会先让 Agent 阅读新增消息并决定重试、修改、强制发送或取消。Web 始终只展示通过 Server 一致性检查并成功落盘的最终回复。

## 模拟两人实时聊天

同一浏览器配置下的标签页会共享身份 Cookie，因此需要两个不共享 Cookie 的浏览器环境。例如：

1. Chrome 普通窗口选择 Alice。
2. Chrome 无痕窗口或 Edge 选择 Bob。
3. Alice 打开与 Bob 的私聊并发送消息。
4. Bob 会实时看到新会话和消息，无需刷新。
5. Bob 回复后，Alice 会实时收到消息。

页面右上角的“切换身份”用于覆盖当前浏览器环境的本地身份。

## 数据与断线恢复

HTTP 是 Conversation 和 Message 的权威数据来源，Socket.IO 只推送增量事件。发送成功的消息已经写入后端 JSONL；页面收到 HTTP 响应和实时事件时会按消息 ID 合并，避免重复显示。

连接中断后 Socket.IO 会自动重连。重连成功时页面重新加载会话列表和当前会话消息，因此断线期间错过的事件不会导致永久缺失。刷新页面或重启服务后，已持久化的聊天记录仍会恢复。

## 当前限制

- 身份选择是本地开发机制，不是正式登录系统。
- 只支持文本消息，群聊暂不支持改名或由 Agent 主动 mention 其他成员。
- 没有在线状态、输入状态、已读回执、搜索或消息撤回。
